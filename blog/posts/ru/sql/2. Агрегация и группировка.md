## 1. Агрегатные функции: считаем метрики

Агрегатные функции принимают множество строк и возвращают одно значение.

### `COUNT()`: считаем строки

```sql
SELECT COUNT(*)
FROM employees;
```

→ 8 (всего сотрудников)

> ⚠️ **Важный нюанс:** `COUNT(*)` считает все строки, включая те, где есть `NULL`.

Если хочешь посчитать только строки, где в конкретном поле есть значение:

```sql
SELECT COUNT(bonus)
FROM employees;
```

→ 4 (только у Анны, Марии, Елены, Дарьи есть премия)

`COUNT(bonus)` игнорирует `NULL`. Это частая причина ошибок: если ты хочешь узнать, сколько сотрудников получают премию, используй `COUNT(bonus)`, а не `COUNT(*)`.

Можно посчитать уникальные значения:

```sql
SELECT COUNT(DISTINCT city)
FROM employees;
```

→ 3 (Москва, СПб, Казань)

### `SUM()`: сумма значений

```sql
SELECT SUM(salary)
FROM employees;
```

→ 760 000 (общий фонд зарплат)

Если в столбце есть `NULL`, `SUM()` их игнорирует. Если все строки `NULL`, результат будет `NULL`.

### `AVG()`: среднее значение

```sql
SELECT AVG(salary)
FROM employees;
```

→ 95 000 (760 000 / 8)

`AVG()` тоже игнорирует `NULL`. Если у тебя 10 сотрудников, но у 3-х зарплата `NULL`, среднее считается по 7.

### `MIN()` и `MAX()`: минимум и максимум

```sql
SELECT MIN(salary), MAX(salary)
FROM employees;
```

→ 70 000 (Андрей), 130 000 (Мария)

Работают не только с числами, но и с датами, строками (лексикографический порядок).

## 2. `GROUP BY`: группируем данные

Агрегатные функции сами по себе возвращают одно число. Но часто нам нужно посчитать метрику для каждой категории.

Например: сколько сотрудников в каждом отделе?

```sql
SELECT department, COUNT(*)
FROM employees
GROUP BY department;
```

Результат:

| department | count |
|------------|-------|
| IT         | 3     |
| Продажи    | 3     |
| Маркетинг  | 2     |

### Как это работает

1. База берёт все строки из `employees`.
2. `GROUP BY department` разбивает их на группы по значению `department`.
3. Для каждой группы считается `COUNT(*)`.

> 💡 **Ключевое правило:** в `SELECT` можно указывать только:
> - поля из `GROUP BY` (по которым группируем)
> - агрегатные функции
>
> Всё остальное — ошибка. Почему? Потому что в группе может быть несколько значений, и база не знает, какое из них показать.

```sql
-- НЕПРАВИЛЬНО:
SELECT department, name, COUNT(*)
FROM employees
GROUP BY department;
```

В отделе IT три сотрудника (Анна, Мария, Павел). Какое имя показать? База не знает, поэтому выдаст ошибку.

### Группировка по нескольким полям

Можно группировать по комбинации полей:

```sql
SELECT department, city, COUNT(*)
FROM employees
GROUP BY department, city;
```

Результат:

| department | city    | count |
|------------|---------|-------|
| IT         | Москва  | 2     |
| IT         | Казань  | 1     |
| Продажи    | СПб     | 2     |
| Продажи    | Москва  | 1     |
| Маркетинг  | Москва  | 1     |
| Маркетинг  | Казань  | 1     |

Каждая уникальная комбинация (`department`, `city`) — отдельная группа.

## 3. `HAVING`: фильтруем группы

`WHERE` фильтрует строки до группировки. `HAVING` фильтрует группы после группировки.

Пример: найдём отделы, где больше 2 сотрудников.

```sql
SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING COUNT(*) > 2;
```

Результат:

| department | employee_count |
|------------|----------------|
| IT         | 3              |
| Продажи    | 3              |

Почему нельзя использовать `WHERE`? Потому что `WHERE` работает до `GROUP BY`, когда групп ещё нет. А `HAVING` — после, когда группы уже сформированы и можно применять агрегаты.

### `WHERE` vs `HAVING`: когда что использовать

**Используй `WHERE`, если фильтр не зависит от агрегатов:**

```sql
-- Сотрудники из Москвы, сгруппированные по отделам
SELECT department, COUNT(*)
FROM employees
WHERE city = 'Москва'
GROUP BY department;
```

→ IT: 2, Маркетинг: 1, Продажи: 1

**Используй `HAVING`, если фильтр зависит от агрегата:**

```sql
-- Отделы, где средняя зарплата больше 100 000
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 100000;
```

→ IT: 120 000

> 💡 **Оптимизация:** если можешь отфильтровать через `WHERE` — делай это. `WHERE` уменьшает количество строк до группировки, что быстрее. `HAVING` фильтрует уже после того, как всё посчитано.

```sql
-- Медленнее (считает агрегат для всех, потом фильтрует):
SELECT department, AVG(salary)
FROM employees
GROUP BY department
HAVING department = 'IT';

-- Быстрее (сразу берёт только IT):
SELECT department, AVG(salary)
FROM employees
WHERE department = 'IT'
GROUP BY department;
```

## 4. Порядок выполнения запроса: полная картина

Теперь, когда ты знаешь `GROUP BY` и `HAVING`, давай соберём полный порядок:

| Этап | Клауза     | Описание                                    |
|------|------------|---------------------------------------------|
| 1    | `FROM`     | → берём таблицу                             |
| 2    | `WHERE`    | → фильтруем строки (до группировки)         |
| 3    | `GROUP BY` | → группируем строки                         |
| 4    | `HAVING`   | → фильтруем группы (после группировки)      |
| 5    | `SELECT`   | → выбираем/считаем столбцы, применяем `DISTINCT` |
| 6    | `ORDER BY` | → сортируем результат                       |
| 7    | `LIMIT`    | → обрезаем результат                        |

### Следствия из порядка выполнения

**1. В `WHERE` нельзя использовать псевдонимы из `SELECT`:**

```sql
-- НЕ РАБОТАЕТ:
SELECT salary * 12 AS annual_salary
FROM employees
WHERE annual_salary > 1000000;
```

Почему? Потому что `WHERE` выполняется до `SELECT`, и псевдоним `annual_salary` ещё не существует.

Правильно:

```sql
SELECT salary * 12 AS annual_salary
FROM employees
WHERE salary * 12 > 1000000;
```

**2. В `WHERE` нельзя использовать агрегаты:**

```sql
-- НЕ РАБОТАЕТ:
SELECT department, COUNT(*)
FROM employees
WHERE COUNT(*) > 2
GROUP BY department;
```

Почему? Потому что `WHERE` выполняется до `GROUP BY`, и групп ещё нет.

Правильно — использовать `HAVING`:

```sql
SELECT department, COUNT(*)
FROM employees
GROUP BY department
HAVING COUNT(*) > 2;
```

**3. В `ORDER BY` можно использовать псевдонимы:**

```sql
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
ORDER BY avg_salary DESC;
```

Почему работает? Потому что `ORDER BY` выполняется после `SELECT`, и псевдоним уже существует.

**4. В `HAVING` можно использовать псевдонимы (в некоторых СУБД):**

В PostgreSQL можно:

```sql
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
HAVING AVG(salary) > 100000;
```

Но в некоторых СУБД (например, MySQL старых версий) нельзя. Лучше писать явно: `HAVING AVG(salary) > 100000`.

## 5. Комбинированные примеры

### Пример 1: Средняя зарплата по отделам, только для отделов с 3+ сотрудниками

```sql
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
HAVING COUNT(*) >= 3
ORDER BY avg_salary DESC;
```

Результат:

| department | avg_salary |
|------------|------------|
| IT         | 120 000    |
| Продажи    | 85 000     |

**Логика:**

1. Группируем по `department`.
2. Оставляем только группы, где `COUNT(*) >= 3` (IT и Продажи).
3. Считаем `AVG(salary)` для оставшихся групп.
4. Сортируем по убыванию средней зарплаты.

### Пример 2: Количество сотрудников в каждом городе, которые получают премию

```sql
SELECT city, COUNT(*) AS bonus_employees
FROM employees
WHERE bonus IS NOT NULL
GROUP BY city;
```

Результат:

| city    | bonus_employees |
|---------|-----------------|
| Москва  | 1               |
| Казань  | 2               |
| СПб     | 1               |

**Логика:**

1. `WHERE bonus IS NOT NULL` — оставляем только тех, у кого есть премия (Анна, Мария, Елена, Дарья).
2. Группируем по `city`.
3. Считаем количество в каждой группе.

### Пример 3: Отделы, где максимальная зарплата больше 100 000, и количество сотрудников

```sql
SELECT department, MAX(salary) AS max_salary, COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING MAX(salary) > 100000;
```

Результат:

| department | max_salary | employee_count |
|------------|------------|----------------|
| IT         | 130 000    | 3              |

## 6. Практика: 8 задач на этот этап

Попробуй решить самостоятельно.

1. Посчитай общее количество сотрудников.
2. Посчитай, сколько сотрудников получают премию.
3. Найди минимальную, максимальную и среднюю зарплату.
4. Посчитай количество сотрудников в каждом отделе.
5. Найди среднюю зарплату в каждом городе.

7. Для каждого города посчитай количество сотрудников, которые получают премию.
8. Найди отделы, где больше 2 сотрудников и средняя зарплата больше 80 000. Отсортируй по убыванию средней зарплаты.
